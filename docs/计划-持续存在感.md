# 计划：让她像一直“活着”（主动联系 v2 → 心事 → 心跳）

> 状态：2026-11-23 草案，待搭档确认。确认前不写代码（AGENTS.md Gate 1）。
> 范围：`astrbot_plugin_reach_out` v2 及后续两步；group_chat_plus（下称 GCP）、chat_rhythm 的配置与小改。
> 实施偏差（2026-11-23 开工后）：① 群里的念头带一个 @她 的组件，AstrBot 原生就能唤醒，所以不注册 predispatch；② 必须改核心补丁 `stage.py` 一处：念头消息不加 @、不加引用（引用一条不存在的消息，OpenQQ 会拒发 1404）；③ `face_convert` 的身份标记（D2）提前到第 1 步做，念头一律标 `[你自己的念头]`。
> 前置：reach_out v1 已上线（PR #23）；`/授权` 参数解析 bug 已在分支 `fix/reach-out-command-args` 修好，重启后生效（见 §2）。

## 1. 目标与原则

**目标**：她给人的感觉像一个一直在的人——各处发生的事她都知道，心里装着事，会自己去找人说话，说过的话有后续。

**为什么现在做不到**：AstrBot 是“收到一条消息才唤醒一次”的模型。每次唤醒时，她只看得到当前会话的聊天记录，回复也只能发回当前会话。跨会话共享的只有人格和 LivingMemory。v1 用工具往别处扔纯文字，绕开了正常回复流程，所以不像她本人在说话。

**四根支柱**（对应后面的步骤）：

| 支柱 | 含义 | 步骤 |
|---|---|---|
| 注意力连贯 | 知道各处刚发生了什么 | 第 1 步「近况」 |
| 自己能过去说话 | 去别的会话时和正常回复一模一样 | 第 1 步「走过去说」 |
| 心里装着事 | 记得答应过谁、牵挂着谁、心情有余温 | 第 2 步「心事」 |
| 自己会动 | 没人找她时，也会想起来去找人 | 第 3 步「心跳」 |

**原则**
1. 能复用 AstrBot、GCP、已有挂钩的就复用，不改核心补丁，不改 GCP 源码。
2. 隐私写进代码：别人的私聊内容不进群、也不进第三人的私聊；搭档的私事不进群。
3. 主动发言宁少勿多。“想了但没说”也算活着。主动越多，小号被风控的风险越高。
4. 每一步都可以单独关掉（插件配置开关），关掉后回到上一步的行为。

## 3. 第 1 步：近况 + 走过去说 + 对话里授权 + 等说完再回

### 3.1 走过去说（`go_talk`）

**用法**：她在任何对话里决定去某处说话，就调用 `go_talk(去哪, 想说什么、为什么)`。
- 去哪：`partner`（搭档私聊），或者 `user`/`group` 加号码。
- 在当前对话里，她正常回一句（比如“好，我去说”）。工具返回的是“已动身”，不是“已说完”，人格里要写明这一点。

**插件做什么**
1. **检查**：
   - 搭档私聊随时能去；其他目标必须在白名单里，并扣额度。限流和去重沿用 v1。
   - 目标就是当前会话时拒绝。
   - 这一轮本身是“念头”触发的时候，禁止再调用 `go_talk`，防止循环。
2. **大约 2 秒后**（等当前回复发完），在目标会话里构造一条消息，用 `platform.create_event()` 和 `commit_event()` 送进正常处理流程。消息内容是她自己的“念头”：
   > 【这是你自己的念头，不是谁发的消息】你刚才在「和搭档私聊」时决定来这里：〈意图〉。直接开口说，不提这条提示，也不说“有人让我来”除非意图里这么写。
3. **发送者**：
   - 群：用一个固定的占位身份（昵称“伽拉忒亚的念头”，号码为配置项，默认 `0`），不冒充任何群友。
   - 私聊：平台要求发送者必须是对方本人，只能用对方的号码，所以完全靠念头的措辞讲清楚“这不是对方说的”。
4. **唤醒**：通过已挂载的 `dafeiyu_hooks.register_predispatch`，只对带插件标记的事件返回 `WAKE`。其他消息一律放行，不影响别人。
5. **构造或投递失败**：退回额度，并记一条“没去成”的近况。

**效果**：她在目标会话里看着那边的聊天记录开口，走正常回复流程，所以分条发送、表情标签转换、`send_meme` 表情包、写进那边的聊天记录、LivingMemory 记忆都和平常一样。

**v1 工具的去留**：
- `message_partner`、`message_contact` **删除**。
- `list_contacts` 保留。
- 抄送搭档**取消**：搭档下次和她私聊时，近况里能看到她去哪说了什么。

### 3.2 对话里授权
- 新增工具 `grant_contact(kind, id, 备注, 天数, 条数)` 和 `revoke_contact(kind, id)`。
- **代码强制**：只有触发这一轮的人是搭档（`event.role == "admin"`，而且发送者在 `admins_id` 里）才生效，否则返回“只有搭档能授权”。群友说“我授权你”无效。
- `/授权`、`/撤销授权`、`/授权列表` 三个命令保留。

### 3.3 近况（跨会话注意力）
- **记什么**：
  - `on_llm_request` 记下“谁在哪说了什么”（触发她的那条，截断到 40 字）；
  - `after_message_sent` 记下“我回了什么”（截断到 60 字）；
  - `go_talk` 的去向和结果也记。
  - 每条带时间和会话。不调用模型。
- **保留**：最近 6 小时、最多 30 条，持久化到 `state.json`。
- **注入**：每次请求时注入一段《你最近在别处》，不包括当前会话自己的内容，大约 300～600 字。
- **隐私矩阵**（代码强制，逐格测试）：

| 当前在哪 \ 近况来源 | 搭档私聊 | 其他人私聊 | 群聊 |
|---|---|---|---|
| 搭档私聊 | 全文 | 全文 | 全文 |
| 其他人私聊 | 不提 | 不提（别人的私聊） | 全文 |
| 群聊 | 只说“和搭档聊过”，不带内容 | 只说“和人私聊过”，不带内容 | 全文（跨群，人格已允许） |

### 3.4 等说完再回
- **私聊**：已经由 chat_rhythm 实现（静默 4 秒、最长 15 秒；“正在输入”时继续等）。核对过 OpenQQ 源码，`onInputStatusPush` 发出的 `notice/notify/input_status` 格式和 chat_rhythm 解析的一致。**待办**：上线后看日志，确认真的收到了“正在输入”通知。
- **群聊**：打开 GCP 自带的等待窗口（只改配置，改前备份）：
  - `enable_group_wait_window = true`
  - `group_wait_window_timeout_ms = 4000`（和私聊一致）
  - `group_wait_window_max_extra_messages = 5`
  - 其余保持默认：@ 消息会开窗口，窗口期内同一人再 @ 一次就立刻回复。
- **念头消息不能被合并**：
  - chat_rhythm 小改：认出插件标记就直接放行，不和对方的连发拼在一起；
  - 群里的念头带 @ 标记，在 GCP 里按 @ 处理，最多等一个窗口期，可以接受。

### 3.5 人格 v0.11
- 删除 v0.10 的“主动联系”条，改写为：
  - 想去哪说话就用 `go_talk`，工具返回的是“已动身”；到了那边像平常一样说话。
  - 搭档让你授权时用 `grant_contact`。
  - 近况是你自己的经历，可以自然提起，但遵守隐私规则。
- 念头的措辞放在插件里，不写进人格。

### 3.6 测试矩阵（`tests/test_reach_out.py` 改写）
- **正常路径**：
  - 从群去搭档私聊；从搭档私聊去授权群；搭档用自然语言授权后再去。
  - `commit_event` 收到的事件：类型、会话、发送者、念头文本、标记都正确。
  - predispatch 只唤醒带标记的事件。
- **失败路径**：
  - 未授权、过期、条数用完时拒绝；非搭档调用授权工具时拒绝。
  - 找不到平台、`commit_event` 抛异常时退回额度。
  - 念头那一轮里调用 `go_talk` 被拒绝。
- **边界**：意图为空、超长；号码不合法；目标就是当前会话；占位发送者号码配置为空。
- **隐私**：§3.3 矩阵的 9 格逐格断言。
- **chat_rhythm**：带标记的私聊事件不进入合并；普通连发合并行为不变（原有测试全部通过）。
- **持久化和并发**：重启后近况、授权都在；并发 `go_talk` 不会超扣额度；损坏的状态文件被移开。
- **全量回归**：`python -m unittest discover -s tests -p "test_*.py"`。

### 3.7 上线与实测（完成判据）
1. 重启前：备份 GCP 配置和数据库，按 §3.4 改 GCP 配置，写入人格 v0.11。
2. 重启后看日志：工具已注册；predispatch 已注册；chat_rhythm 收到了“正在输入”。
3. QQ 实测（搭档执行）：
   - 私聊说“去跑团群跟大家说一声 X”：她在私聊回“我去说”，群里出现她自己口吻的话（分条，能带表情）。
   - 回私聊问“刚才在群里说了啥”，她答得上来（近况生效）。
   - 在群里连发 3 条短句后 @ 她：只得到一次回复（等待窗口生效）。
   - 让群友在群里叫她“去私聊某个没授权的人”：被拒绝。
   - 在群里问她“搭档刚才私聊你什么了”：她不说内容（隐私生效）。

### 3.8 风险
1. **GCP 对构造的群消息的处理**：GCP 有 1.2 万行，静态读不全。可能被判成“不回”、被当成普通群友存进它的缓存，或者念头文本出现在她看到的群聊记录里。**对策**：实测第一条；如果被判成不回，改为同时带 At 标记，并加入 GCP 的 @ 合并名单配置。
2. **念头进入聊天记录和 LivingMemory 的样子**：会作为一条“占位身份说的话”留下来。措辞要保证以后回看时不会误以为是别人说的。实测后检查 LivingMemory 生成的摘要。
3. **私聊发送者只能是对方本人**：face_convert 的身份标记会显示成对方的名字。可能要在 face_convert 里识别插件标记、改成“[你的念头]”。这是小改，实测后再决定。
4. **对方不是 QQ 好友时私聊发不出去**：她当场不会知道。近况会显示“去了但没说出口”（没有收到发送成功的回调），下次问起时她能如实说。

### 3.9 不做
心跳、心事账本、情绪动态；不改 GCP 源码；不改核心补丁。

## 4. 第 2 步：心事（答应过的事、牵挂、心情余温）

### 4.1 心事账本
- **内容**：每条心事包括：关于谁、在哪、什么事、什么时候该想起、什么时候过期、状态（挂着 / 已办 / 放下）。例如“小明明天考试”“答应搭档开团前提醒”“搭档说今晚熬夜”。
- **怎么记**（待决定 D3）：
  - (a) 她自己调用工具 `keep_in_mind(...)`：答应了、在意了就记。省钱，和人设“认真记住别人说的话”一致，但可能漏记。
  - (b) 每轮结束后用便宜模型抽取：记得全，但每轮多一次调用。
  - **推荐**：(a) 为主，每晚用一次 (b) 从近况里补漏。
- **怎么用**：每次请求时注入“挂着的心事”，最多 5 条，只注入和当前会话、当前人有关的，以及到期的。
- **复用**：`affective_core` 的 `care_threads` 表结构和过期逻辑（`core.py` 第 261～520 行）可以直接借用。
- **不能原样部署 affective_core**：它是按旧版大肥鱼写的，用的是“主人”这个称呼和“傲娇黏人、哄一下就软”的设定，和现在的人设（平等的朋友、不依附）冲突。只取数据结构和衰减公式，称呼和表达部分重写。

### 4.2 心情余温（可选，排在心事账本之后）
- 用 affective_core 的连续动力学：被逗、被夸、被冷落留下余温，隔夜回落。注入时只用文字描述体感，不出现数值。
- 去掉“傲娇软化门控”“主人私聊专属”等旧设定。
- **待决定 D4**：要不要做。不做也不影响“活着”的主体感受。

### 4.3 测试要点
心事的增删改；到期和过期；跨会话可见性（同样遵守 §3.3 的隐私矩阵）；重启后保留；补漏抽取失败时不影响对话。

## 5. 第 3 步：心跳（没人找她时也会想起来）

### 5.1 机制
- **频率**：后台任务，白天每 45 分钟醒一次，按北京时间 09:30～23:30。宿主机时区是 UTC+11，必须显式用 `Asia/Shanghai`。
- **判断**：用便宜模型看“到期的心事 + 近况 + 现在几点 + 今天已经主动过几次”，输出 `{要不要动, 去哪, 想说什么, 理由}`。**默认不动**，提示词里写明“大多数时候什么都不做”。
- **执行**：要动就调用第 1 步的 `go_talk`，同样受白名单、限流、去重约束。
- **刹车**：
  - 夜间不发；
  - 每天主动上限，起步是搭档私聊 2 次、群 0 次；
  - 同一件心事只提一次；
  - 对方最近 30 分钟在和她聊天时，不另起话头；
  - 对方连续两次没理她主动发的消息，就把这件心事放下。

### 5.2 和现有主动机制的关系（待决定 D5）
- GCP 自带“主动对话”，目前只在跑团群开着，它只看群里冷场，不知道心事。AstrBot 的定时任务（`future_task`）是到点执行的约定。
- **推荐**：心跳只管私聊和跨会话的主动；群里冷场暖场暂时继续交给 GCP。观察一段时间后再决定是否全部收归心跳。两者同时触发时以“今天已主动次数”为准，互相计数。

### 5.3 分阶段放开
1. 只对搭档私聊开放，运行 3～7 天，看是否烦人、是否触发风控。
2. 开放给授权的私聊。
3. 最后考虑群。

### 5.4 测试要点
时区边界（UTC+11 宿主机）；每日上限；默认不动；心跳失败不影响对话；关掉开关后完全不触发。
