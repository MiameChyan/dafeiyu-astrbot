# Windows 日常启动与安全关闭

使用仓库根目录的 `启动大肥鱼.ps1` 和 `安全关闭大肥鱼.ps1`。本机项目上一级目录也放有相同入口。
右键文件，选择“使用 PowerShell 运行”；结果窗口会等待回车。
`.ps1` 的双击行为取决于 Windows 文件关联，可能会打开编辑器。

在项目目录的 PowerShell 中，也可以运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\启动大肥鱼.ps1 -NoPause
powershell -NoProfile -ExecutionPolicy Bypass -File .\安全关闭大肥鱼.ps1 -NoPause
```

`-ExecutionPolicy Bypass` 仅应用于本次进程，不修改系统执行策略。脚本兼容 Windows PowerShell 5.1 和 PowerShell 7，中文脚本使用 UTF-8 BOM。

## 现在的组成（2026-11-16 起）

| 部分 | 在哪 | 谁管 |
|---|---|---|
| AstrBot（她的大脑） | Docker 容器 `dafeiyu-windows-astrbot-1` | 启停脚本 |
| AstrBot 数据（对话历史、配置、知识库、插件数据库） | Docker 数据卷 `dafeiyu-astrbot-data` | 启停脚本只用不删 |
| 插件代码、插件配置 | 宿主机 `deploy-windows\data\plugins\`、`data\config\`（挂进容器） | 直接改文件 |
| QQ 协议端 | 宿主机上的 OpenQQ（`.env` 的 `OPENQQ_DIR`），在单独的窗口里运行 | 启动脚本拉起，关闭脚本不动 |
| 掉线监控 | 后台 `pythonw watchdog.py` | 启停脚本 |
| NapCat | 已停用，放在 compose 的 `napcat` profile 里 | 启动脚本发现它在跑会先停掉 |

数据不再放在 Windows 目录里：SQLite 在 Docker Desktop 的 Windows 绑定挂载上会写坏。2026-11-16 出过一次，对话历史从某一刻起一直写不进去，她每次回复都看不到前文，所以答非所问。
`deploy-windows\data\` 里现在只有 `plugins\`、`config\` 有效；`_migrated_to_volume_*` 是迁移前的旧文件，只作备份，改了也不生效。**聊天配置改用 AstrBot 面板。**

## 启动做了什么

1. 需要时启动 Docker Desktop，等引擎就绪（默认最多 180 秒）。
2. NapCat 容器如果在跑就先停掉：它登的是同一个小号，会和 OpenQQ 互相顶号。
3. 确认数据卷存在且里面有 `data_v4.db`；没有就停下，不会起一个空白的大肥鱼。
4. `docker compose up -d --no-deps --no-build --pull never astrbot`：只在 compose 配置变了时重建 AstrBot 容器，否则只是启动或保持运行。不构建、不联网拉镜像、不碰 NapCat。
5. 等 AstrBot 面板能访问（默认最多 180 秒）。
6. OpenQQ：
   - 已经在跑就直接用；
   - 没在跑：如果有 QQ 开着就停下，请你先退出所有 QQ（OpenQQ 必须自己拉起 QQ 才能挂接）；否则在新窗口里运行 `node src/main.mjs start`，**这个窗口要一直开着**。在它拉起的 QQ 里登录小号，需要主号就等登录完再另开 QQ。
   - 等 `OPENQQ_DIR\.runtime\status.json` 变成 `session_ready`（默认最多 300 秒；上次运行留下的旧状态不算）。被踢下线、挂接出错会直接报出来。
   - 再等 OpenQQ 连上 AstrBot 的 6199 端口（最多 60 秒）。
7. 都好了才启动掉线监控，最后打印面板地址。

任何一步失败都会报错退出，已经起来的部分保持原样。修好之后**重新运行启动脚本即可**，它不会重复拉起已经在跑的东西。

## 关闭做了什么

1. 核实监控 PID 的完整脚本路径，然后停止掉线监控。
2. 让 AstrBot 正常退出（默认最多 120 秒），SQLite 会在退出时把 WAL 写回主库。compose 让 Docker 发 SIGINT（AstrBot 是容器里的 PID 1，只处理 SIGINT），实测两三秒就能退出。NapCat 若被手动开过也一起停。
3. 检查退出码。137、OOM 或其他异常退出会报错，并保留 Docker 以便检查，不会宣称正常收尾。
4. OpenQQ 和 QQ **保持登录**，下次启动不用重新登录。要彻底下线：在 OpenQQ 窗口按 Ctrl+C，再退出它拉起的 QQ。
5. 没有其他容器在跑时退出 Docker Desktop 并核实已停止；有其他容器就保留 Docker 并列出名称。

Docker 已关闭时，重复关闭会正常返回。引擎无法连接但 Desktop 仍运行时会报错，不会强杀 Docker。

所有日常操作都保留数据卷、插件目录、配置、镜像、容器与网络，不执行 `down`、删除或清理命令。只操作本机 Windows Docker；远程 Docker 上下文会被拒绝。同时运行多个日常启停脚本会报错，避免相互打断。

## 可选参数

```powershell
.\启动大肥鱼.ps1 -NoPause -NoWatchdog            # 不启用 QQ 掉线监控
.\启动大肥鱼.ps1 -NoPause -NoOpenQQ              # 不管 OpenQQ（自己拉起协议端时用）
.\启动大肥鱼.ps1 -NoPause -LoginTimeoutSeconds 600
.\安全关闭大肥鱼.ps1 -NoPause -KeepDocker        # 停大肥鱼，保留 Docker
.\安全关闭大肥鱼.ps1 -NoPause -StopTimeoutSeconds 300
```

这些入口不会主动提权。若 Windows 报 Docker 管道或进程访问被拒绝，可在有 Docker Desktop 使用权限的 PowerShell 中重试。

## 其他脚本

- `deploy-windows\start.ps1`：首次部署、重建镜像。全新部署时会创建空的数据卷；发现 `.\data` 里还有没迁移的旧数据会拒绝启动。
- `deploy-windows\migrate-data-volume.ps1`：一次性把旧的 `.\data` 迁进数据卷（先 `安全关闭大肥鱼.ps1 -KeepDocker`）。已迁移过会拒绝，不覆盖。
- `deploy-windows\stop.ps1`：旧的停止脚本，仍可用。

## 备份数据卷

```powershell
docker run --rm --mount type=volume,source=dafeiyu-astrbot-data,target=/d,readonly `
  --mount "type=bind,source=$PWD,target=/out" --entrypoint tar dafeiyu-astrbot:windows `
  -czf /out/dafeiyu-data-$(Get-Date -Format yyyyMMdd).tgz -C /d .
```

请在 AstrBot 停止时备份（`安全关闭大肥鱼.ps1 -KeepDocker`），确保数据库已写回主库。
